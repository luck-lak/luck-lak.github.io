Chapter 1: Manipulation

SQL Basics Summary

Congratulations! We’ve learned six commands commonly used to manage data stored in a relational database and how to set constraints on such data. What can we generalize so far?

SQL

SQL is a programming language designed to manipulate and manage data stored in relational databases.

  • A relational database is a database that organizes information into one or more tables.
  • A table is a collection of data organized into rows and columns.

A statement is a string of characters that the database recognizes as a valid command.

SQL Commands

  • CREATE TABLE creates a new table.
  • INSERT INTO adds a new row to a table.
  • SELECT queries data from a table.
  • ALTER TABLE changes an existing table.
  • UPDATE edits a row in a table.
  • DELETE FROM deletes rows from a table.

Constraints

Constraints add information about how a column can be used.

Chapter 2: Query

SQL Querying and Filtering Summary

Congratulations!

We just learned how to query data from a database using SQL. We also learned how to filter queries to make the information more specific and useful.

Querying and Filtering Commands

  • SELECT is the clause we use every time we want to query information from a database.
  • AS renames a column or table.
  • DISTINCT returns unique values.
  • WHERE filters the results of a query based on specified conditions.
  • LIKE and BETWEEN are special operators used for filtering data.
  • AND and OR combine multiple conditions.
  • ORDER BY sorts the query result.
  • LIMIT specifies the maximum number of rows that the query will return.
  • CASE creates different outputs based on different conditions.

Key Idea

SQL queries can be made more useful by combining:

SELECT + filtering conditions + sorting + limiting results

This allows us to retrieve only the data we actually need.

Chapter 3: Aggregate Functions

SQL Aggregate Functions Summary

Congratulations!

You just learned how to use aggregate functions to perform calculations on your data.

Aggregate Functions

Aggregate functions combine multiple rows together to form a single value of more meaningful information.

  • COUNT() counts the number of rows.
  • SUM() calculates the sum of the values in a column.
  • MAX() returns the largest value.
  • MIN() returns the smallest value.
  • AVG() calculates the average of the values in a column.
  • ROUND() rounds values to a specified number of decimal places.

Grouping Data

  • GROUP BY is used with aggregate functions to combine data from one or more columns into groups.
  • HAVING filters the results of a query based on an aggregate property.

Key Idea

Aggregate functions summarize data, while GROUP BY lets us calculate summaries for different groups.

HAVING is used to filter those groups based on aggregate results.

Chapter 4: Multiple Tables

SQL Relationships and Joins Summary

In this lesson, we learned about relationships between tables in relational databases and how to query information from multiple tables using SQL.

Table Relationships

  • A primary key is a column that serves as a unique identifier for the rows in a table.
  • A foreign key is a column that contains the primary key of another table.

Primary keys and foreign keys are used to create relationships between tables.

SQL Joins

  • JOIN combines rows from different tables when the join condition is true.
  • LEFT JOIN returns every row from the left table. If there is no matching row in the right table, NULL values are used for the right table’s columns.
  • CROSS JOIN combines every row of one table with every row of another table.

Combining Query Results

  • UNION stacks one dataset on top of another.
  • WITH allows us to define one or more temporary result sets that can be used in the final query.

Key Idea

Relational databases connect tables through keys.

JOIN combines related columns horizontally, while UNION combines compatible query results vertically.

WITH helps break complex queries into smaller, easier-to-read parts.

Chapter 5: Subqueries

SQL Subqueries Summary

Congratulations on taking another step in the SQL journey.

In this lesson, we learned how to use subqueries in SQL.

Subqueries

A subquery is a query nested inside another SQL statement.

Subqueries can be useful when we want to use the result of one query as part of another query.

Using Subqueries

Subqueries can be used with:

  • SELECT
  • INSERT
  • UPDATE
  • DELETE

They can also be combined with comparison operators.

Common Subquery Operators

  • IN checks whether a value exists in the result of a subquery.
  • NOT IN checks whether a value does not exist in the result of a subquery.
  • EXISTS checks whether a subquery returns any rows.
  • NOT EXISTS checks whether a subquery returns no rows.

Key Idea

A subquery allows one SQL query to depend on the result of another query.

This can make complex filtering and data manipulation easier to express.

SQLite Summary

What is SQLite?

SQLite is a database engine that allows users to interact with a relational database.

Unlike many other database systems, an SQLite database is stored in a single file.

This makes SQLite highly portable:

  • Copying a database is as simple as copying a file.
  • Sharing a database can be as simple as sending the database file.
  • SQLite does not require a separate database server.

Key Features

  • Lightweight and easy to set up.
  • Stores the entire database in a single file.
  • Does not require a separate server process.
  • Works well for local applications, development, and testing.
  • Supports standard relational database concepts and SQL.

Drawbacks

SQLite also has some limitations.

Concurrent Writing

SQLite is not ideal when many users need to modify the database at the same time.

Only limited concurrent writing is supported, so larger multi-user systems usually use server-based databases instead.

Security

Because the database is stored as a local file, developers need to manage access to that file carefully when storing private data.

Fewer Advanced Features

SQLite does not provide all of the advanced functionality available in larger database systems.

Flexible Data Types

SQLite uses a more flexible type system than many other relational databases.

For example:

</> SQL
CREATE TABLE celebs (
    id INTEGER,
    name TEXT,
    age INTEGER
);

The schema indicates the expected data types, but SQLite may still allow values of other types to be stored in these columns.

Therefore, it is important to keep the data consistent even when SQLite itself is permissive.

Common Use Cases

SQLite is commonly used for:

  • Learning and practicing SQL
  • Local application databases
  • Development and testing
  • Small projects
  • Desktop applications
  • Mobile applications
  • Applications where the database and application are stored on the same device

Basic Usage

A database can be opened or created from the terminal with:

</> Shell
sqlite3 newdb.sqlite

This opens the SQLite command-line interface:

</> SQLite prompt
sqlite>

To exit:

</> SQLite
.exit

Key Idea

SQLite is a lightweight relational database engine that stores an entire database in a single file.

Its biggest advantages are:

simple + portable + serverless

This makes SQLite especially useful for learning SQL, local development, testing, and small applications.

SQL Window Functions Summary

What is a Window Function?

A Window Function performs calculations across a group of related rows while still keeping each original row.

This is the main difference from GROUP BY.

Window Function vs GROUP BY

GROUP BY:

  • Groups multiple rows together.
  • Usually reduces several rows into one result row.

Window Function:

  • Performs calculations over related rows.
  • Keeps every original row in the result.

Basic Syntax

</> SQL
function() OVER (
    PARTITION BY ...
    ORDER BY ...
)

The OVER() clause turns a function into a window function.

PARTITION BY

PARTITION BY divides rows into groups for the window calculation.

It is similar to GROUP BY, but it does not remove the original rows.

Example:

</> SQL
AVG(salary) OVER (
    PARTITION BY dept
)

This calculates the average salary for each department while keeping every employee row.

ORDER BY

ORDER BY inside OVER() defines the order of rows within the window.

It is commonly used for:

  • Ranking
  • Numbering rows
  • Running totals

Example:

</> SQL
RANK() OVER (
    PARTITION BY dept
    ORDER BY salary DESC
)

This ranks employees by salary within each department.

Common Window Functions

  • AVG() OVER(...) calculates a window average.
  • SUM() OVER(...) calculates a window sum.
  • COUNT() OVER(...) calculates a window count.
  • RANK() OVER(...) assigns rankings.
  • ROW_NUMBER() OVER(...) assigns a unique number to each row.

Key Idea

Window Functions are useful when we want to calculate statistics or rankings without losing the original rows.

A simple way to remember:

GROUP BY
→ group and reduce rows

Window Function
→ group and calculate, but keep rows
