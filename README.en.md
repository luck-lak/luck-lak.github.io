# Aokun's personal website

[Visit the site](https://luck-lak.github.io/) · [中文版](README.md)

This is where I keep my projects, course records, and blog. I'm an undergraduate in Intelligent Science and Technology at Nanjing University. My focus is gradually moving from web development and broad technical exploration toward data mining and machine learning.

The site uses HTML, CSS, and a little JavaScript. Jekyll builds the blog, and GitHub Pages hosts the site. The structure stays simple so I can understand and maintain it myself.

## Where to make changes

| Content | File |
| --- | --- |
| About, current focus, projects, learning journey, contact | `index.html` |
| Learning records hub and future notebook entry | `learning-records.html` |
| Width, typography, dark mode, mobile layout | `css/style.css` (with section comments) |
| Theme switching and persistence | `js/main.js` |
| Blog introduction | `blog/index.html` |
| Blog posts | `_posts/` |
| Blog navigation and layouts | `_includes/`, `_layouts/` |
| Course lists and detail pages | Generated by scripts in `tools/`; see below |

Site introductions are mostly in English, course notes mix Chinese and English, and the blog is mainly in Chinese. **Edit the Chinese `README.md` first, then synchronize this file.** GitHub displays the Chinese version by default.

## Preview locally

From the site root, with Python installed:

```powershell
python -m http.server 8000 --bind 127.0.0.1
```

Open the [local homepage](http://127.0.0.1:8000/). Replace `python` with `py` if that is your installed command.

This previews the homepage and learning records. **It does not build the Jekyll blog.** Check the full blog after GitHub Pages builds it, or build locally with a configured Ruby/Jekyll environment.

## Update the homepage

Each section is written directly in `index.html`:

- `#about-me`: a short introduction.
- `#current-focus`: current studies and next steps.
- `#projects`: projects I've actually built.
- `#technical-journey`: the compact Learning Journey; the original anchor remains compatible with existing links.
- `#learning-records`: course records and the future data notebook entry.
- `#contact-me`: contact information.

To add a project, copy an `<article class="project-card">` inside `.project-list` and update its title, real repository link, and description. CSS changes are usually unnecessary.

The data notebook repository is not available yet, so its entry is marked **Planned**. Once the first notebooks are ready, replace the description with a real link and update the records hub and GitHub profile.

Describe completed work, current learning, and plans accurately. Course exposure should not be presented as project experience, and plans should not be presented as completed work.

## Adjust the layout

Search for class names and section comments in `css/style.css`:

| Selector | Purpose |
| --- | --- |
| `.home-page` | Homepage width, currently capped at 1200px including side padding |
| `#about-me`, `.personal-img` | Introduction and portrait columns |
| `.focus-grid`, `.notes-grid` | Current focus and notebook entries |
| `.project-list` | Project grid |
| `.journey-list` | Learning journey list |
| `.records-*`, `.record-*` | Course lists and details |
| `.blog-*`, `.post-*` | Blog list and posts |
| `body.dark-mode` | Dark theme |
| `@media` | Narrow layouts and reduced motion |

The navigation uses `position: sticky` and occupies normal document space. There is no need to guess a fixed top offset for the main content when navigation changes. The homepage can be wider while long blog posts keep a narrower reading measure.

After a layout change, check desktop at 100% zoom, mobile widths, both themes, and navigation anchors.

## Maintain learning records

`learning-records.html` is the manually maintained hub; `learning/` contains platform lists; `records/` contains course and paper detail pages.

| Platform | Generator | Source notes |
| --- | --- | --- |
| DeepLearning.AI | `tools/build_learning_records.py` | `学习探索记录.docx` in the site root |
| Codecademy | `tools/build_codecademy_records.py` | A sibling `codecademy/` folder next to the site folder |

Edit source notes or the generator before rebuilding. Direct edits to generated HTML will be overwritten. Preserve original wording, screenshot order, and links; maintain site introductions and navigation in the templates.

For Codecademy, `PLATFORM_INTRO` holds the list introduction and `PLATFORM_PREFACE` preserves the original personal preface. To add a course:

1. Place the notes in the sibling `codecademy/` folder.
2. Add `file`, `title`, `slug`, and `kind` to the script's `RECORDS`, following the existing format examples.
3. Add a numbered SVG cover under `assets/records/thumbnails/codecademy/`.
4. Run the generator and check the list, detail page, and previous/next links.
5. Update the platform count in `learning-records.html` manually.

```powershell
python -m pip install python-docx Pillow
python tools/build_codecademy_records.py
# After updating the DeepLearning.AI source notes:
python tools/build_learning_records.py
```

If the website checkout and Codecademy notes are not siblings, set `CODECADEMY_NOTES_DIR` in the terminal that runs the generator instead of hard-coding a machine-specific path:

```powershell
$env:CODECADEMY_NOTES_DIR = "<path to Codecademy notes>"
python tools/build_codecademy_records.py
```

DeepLearning.AI covers live under `assets/records/thumbnails/`, named by record number; special extensions are configured in `RECORD_COVER_EXTENSIONS`. This platform offers the original DOCX download; Codecademy pages do not.

`inspect_docx.py` and `list_record_links.py` are inspection helpers and do not run as part of the site.

## Write a blog post

Create `_posts/YYYY-MM-DD-post-slug.md`:

```markdown
---
layout: post
title: "A data analysis exercise"
lang: en
date: 2026-09-05 12:00:00 +0800
description: "The question, process, and lessons from this exercise."
---

Start writing here.
```

The published URL is `/blog/post-slug/`. Future-dated posts remain hidden by default. Use `lang: zh` for Chinese posts.

Put images under `assets/images/blog/post-slug/` and reference them as `/assets/images/blog/post-slug/image.png`. Optional front matter adds a cover to the blog list:

```yaml
cover: "/assets/images/blog/post-slug/cover.jpg"
cover_alt: "A description of the image"
```

Blog navigation comes from `_includes/site-header.html`. The homepage and learning records use plain HTML, so navigation changes also need to reach their pages or generator templates.
